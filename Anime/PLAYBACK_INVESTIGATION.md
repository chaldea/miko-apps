# 问题 2：媒体 CDN 出口与 5 秒弹窗复查

本次复测日志日期：2026-11-10（北京时间）。

媒体文件没有整体失效。同一个 MP4 URL 在原出口连接被重置，更换出口后返回有效数据。用户提供的“出口 IP 被列入黑名单”与这个现象相符，但本次对照不能区分 IP 黑名单、地域/线路限制或中间网络设备的干预，更不能确定首次触发条件。

## 代理复测

所有视频探测均使用 `Range: bytes=0-4095`、`User-Agent: libmpv`，最多读取 4096 字节，不做批量分集探测，也不自动重试。这里的 User-Agent 是探测参数，不是对原版实际线上请求头的抓包结论。未添加 Referer、Cookie 或媒体 Authorization。

| 路径 | 证据 | 结果 |
| --- | --- | --- |
| 显式直连 | 不使用系统 HTTP 代理 | TLS 连接重置，未收到 HTTP 响应 |
| `127.0.0.1:7890` | Mihomo 日志：目标域名命中 `GeoIP(cn)`，最终为 `DIRECT` | TLS EOF；没有真正更换出口 |
| 临时独立代理，使用当前选中的上游节点 | 同一出口检测服务确认公网 IP 不同、地区从 CN 变为 US；媒体域名日志确认走该节点 | 旧 URL 返回 `206`、`video/mp4`、4096 字节，包含 `ftypisom` |
| 同一临时代理重新登录、获取详情、解析分集 | 标题 5415 首集，解析结果与旧 URL 完全相同 | 解析成功；等待 5 秒后媒体同样返回 `206` 和有效 MP4 头 |

旧 URL 的读取在本次重新登录、解析之前已经成功，未执行原版弹窗或广告回调。因此没有证据表明恢复访问依赖广告完成回执。额外等待 5 秒的探测仅用于核对用户提出的假设，不是新发现的协议要求。

临时代理只供诊断进程显式使用，绑定回环地址，运行结束后停止并删除临时配置；没有修改 Clash 的全局模式、订阅、现有分流规则或系统代理。`7890` 的日常配置仍对该域名直连。

此次只确认能够重新解析并读取媒体数据；没有将读取文件头当成全片播放成功，也没有把诊断代理接入正式应用。Miko 的 Android/Windows 视频传输由各平台原生播放器处理，给 `LanercClient` 设置 HTTP 代理不会自动改变原生媒体传输的路由。

## 原版 5 秒弹窗调用链

证据来自 APK 的 arm64 `libapp.so`，通过已有 Blutter 对象池与 Capstone 补充反汇编交叉核对。混淆后的方法名不具备业务语义，以下使用地址与已恢复的字符串描述行为。

| 地址 | 已确认行为 |
| --- | --- |
| `0x920938` 的媒体打开函数 | `0x920c48` 创建 `Vab` 媒体对象，`0x920c68` 调用构造函数，`0x920c84` 调用播放器打开方法，随后 `0x920ce0` 调用播放方法；`0x920fd0` 才启动 `0x921010` 的广告流程。 |
| `0x5fa854` | 此媒体构造分支接受 URL 与可选的 `start`，调用现场没有传入自定义 `httpHeaders`。 |
| `0x921010` | 检查当前播放任务及广告条件，调用暂停方法 `0x9220e0` 后打开弹窗 `0x9215c0`；异常日志为“播放后广告流程失败”，并存在恢复播放分支。 |
| `0x9215c0` | 初始化本地计数为 5、文本“暂时跳过 5秒”，启动计时器并显示支持弹窗。 |
| `0x661698` | 每次计时递减本地计数并更新文本；结束后记录“倒计时结束”、取消计时器。没有网络请求、播放 URL 更新或凭证获取。 |
| `0x663a58` | 未到时间时提示“还不能关闭”；可跳过时更新本地状态、关闭弹窗，并显示“虽然您没有观看广告，但是您依然可以使用”。这条分支没有广告完成上报。 |

激励广告的 `loadReward`、`onVideoRewarded` 等回调是另外的分支，不能与用户等待 5 秒后“暂时跳过”的行为混同。上述结论限定于已核对的普通播放及跳过路径，不代表整个广告 SDK 没有任何网络请求。

因此，当前证据不支持“因为 Miko 没弹出 5 秒提示而被封禁”。即使补上相同 UI，也不能据此解决现有出口限制。

## 请求头、重试与触发原因

- 原版使用 media_kit/libmpv；当前应用通过 Miko 调用 Windows Media Foundation 和 Android MediaPlayer。底层 HTTP/TLS 实现存在差别，但尚无证据将某种客户端指纹认定为封禁原因。
- 已发现的 `Referer: https://douban.com` 与浏览器 User-Agent 常量属于图片路径，不应套用到视频 CDN。视频对照在没有 Referer、Cookie、媒体 Authorization 的条件下成功。
- 原版下发的播放器选项包括 `reconnect=1,reconnect_streamed=1,reconnect_on_network_error=1,reconnect_delay_max=5`，以及 HLS 的 `seg_max_retry=10`。它本身存在网络重连；`reconnect_delay_max=5` 是最大重连延时，不是播放前必须等 5 秒。
- 当前 `DetailContent.Resolve()` 在加载、手动选集/换线路或重试时解析一次；`AsyncPage.Run()` 阻止忙碌期间重入。检查到的应用与 Miko 会话代码在错误后没有自动循环重新解析/加载。平台播放器内部可能自行产生 Range 请求或重试，本次未对其完整网络行为抓包，不能宣称每次播放只有一个 HTTP 请求。
- 之前诊断曾请求多个分集，但缺少 CDN 拦截记录、首次封禁时间与请求日志，不能将它们或未展示的弹窗直接认定为触发原因。要确定触发规则，需要对应出口、时间与域名的 CDN/WAF 日志。

应用代码本轮没有增加等待、伪造广告回执、添加猜测性视频头或修改解码器。若要用本机代理恢复原生播放，需确保视频连接实际经过可用出口；只为 API 的 HttpClient 配置代理不足以完成这一点。
